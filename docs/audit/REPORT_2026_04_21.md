## 3. Top 5 Architectural Debts

### 1. MCP Router Has No Authentication

- **What:** The MCP SSE endpoint at `/api/mcp/sse` is publicly accessible without any auth middleware.
- **Where:** `backend/routers/mcp.py` lines 98-118 — no `Depends(get_current_user)` or role guards.
- **Risk:** Any external AI agent (or attacker) can query order statistics and list active orders without credentials. This bypasses the entire security model.
- **Effort:** S (add dependency, 10 lines)

### 2. OrderDetailPanel Exceeds Maintainable Size

- **What:** At 439 lines, this component handles status changes, debounced saves, attachment uploads, shipping label generation, financial calculations, and timeline rendering.
- **Where:** `frontend/src/components/orders/OrderDetailPanel.tsx` — entire file.
- **Risk:** Future modifications (e.g., adding more panels) will increase cognitive load. Testing individual behaviors becomes difficult. Violates React best practices for component composition.
- **Effort:** M (extract 3-4 subcomponents: `OrderNotesPanel`, `AttachmentManager`, `ShippingPanel`, `OrderTimeline`)

### 3. NewOrderDialog Combines Form Logic with Price Calculation

- **What:** 320 lines mixing UI state, item array management, and total price computation.
- **Where:** `frontend/src/components/orders/NewOrderDialog.tsx` — lines 56-66 (item state), lines 66 (price calc), lines 68-103 (submit logic).
- **Risk:** Adding validation rules or multi-currency edge cases will bloat this further. Logic should be extracted to a custom hook.
- **Effort:** M (extract `useOrderForm` hook, split item management into `OrderItemsEditor` component)

### 4. External Services Lack Timeout and Retry Configuration

- **What:** `nova_poshta.py` and `shopify_sync.py` use `httpx.AsyncClient()` without explicit timeout or retry logic.
- **Where:** 
  - `backend/services/nova_poshta.py` line 22 — `async with httpx.AsyncClient() as client:`
  - `backend/services/shopify_sync.py` line 29 — same pattern
- **Risk:** Network hangs or rate-limit responses from external APIs will block the scheduler indefinitely. No exponential backoff for transient failures.
- **Effort:** M (add `timeout=30.0` and `retry` decorator with exponential backoff)

### 5. etsy_parser.py Swallows Errors Per-Row Without Aggregate Reporting

- **What:** Errors during CSV parsing are logged individually (line 132-133) but the import succeeds even if 50% of rows fail.
- **Where:** `backend/services/etsy_parser.py` lines 131-133 — `logger.exception()` inside loop, no aggregate failure threshold.
- **Risk:** Silent data loss. User sees "Imported 50 orders" but doesn't know 50 more failed. No mechanism to download error report.
- **Effort:** M (add error threshold, return detailed error report to frontend, allow re-download of failed rows)

## 4. Roadmap

### Phase 1 — Stabilization (fix before any new features)

| File | Change Required | Priority |
|------|-----------------|----------|
| `backend/routers/mcp.py` | Add `Depends(get_current_user)` to `/sse` and `/messages` endpoints. Consider requiring `OWNER` role only. | 🔴 Critical |
| `backend/services/nova_poshta.py` | Add `timeout=30.0` to `httpx.AsyncClient()`. Wrap `_post()` in retry decorator (3 attempts, exponential backoff). | 🟠 High |
| `backend/services/shopify_sync.py` | Same timeout and retry pattern. Add explicit error logging with shop context. | 🟠 High |
| `backend/services/etsy_parser.py` | Add error threshold (e.g., fail if >20% rows error). Return `ImportResult` with error details to frontend for user review. | 🟠 High |
| `task.md` | Update to reflect Sprint 11 as current (not Sprint 2). | 🟢 Low |

### Phase 2 — Core Flow Hardening

**Focus:** Order → Status → History lifecycle integrity

| File | Change Required | Rationale |
|------|-----------------|-----------|
| `backend/services/order_service.py` | Extend history logging to cover `update_order()` mutations (financial fields, shipping data). Currently only status changes are audited. | Full audit trail requirement from `ORDERHUB_CONTEXT.md` |
| `backend/models/order.py` | Add database-level check constraint for status transitions (optional, defense-in-depth). | Prevent bypass via direct DB access |
| `frontend/src/hooks/useOrders.ts` | Verify `queryClient.invalidateQueries()` is called after `useUpdateOrderStatus` mutations. | Ensure UI consistency |
| `frontend/src/components/orders/OrderDetailPanel.tsx` | Extract subcomponents (see Debt #2). Add unit tests for each panel. | Maintainability |
| `frontend/src/components/orders/NewOrderDialog.tsx` | Extract `useOrderForm` hook and `OrderItemsEditor` component (see Debt #3). | Maintainability |

### Phase 3 — Expansion Readiness

**Preconditions for activating Shopify, Etsy, and Nova Poshta in production:**

| Requirement | Current State | Gap |
|-------------|---------------|-----|
| **Timeout configuration** | Missing | Add to all `httpx` clients |
| **Retry with backoff** | Missing | Implement for all external API calls |
| **Error reporting to user** | Partial (etsy only) | Extend to Shopify sync and TTN generation |
| **Rate limit handling** | Not implemented | Detect `429` responses and queue for retry |
| **Credential rotation** | Encryption exists, no rotation logic | Add periodic re-encryption or manual rotation endpoint |
| **Monitoring hooks** | None | Add structured logging with correlation IDs for sync jobs |
| **Manual override** | Partial (manual sync trigger exists) | Add UI for viewing sync history and re-running failed syncs |
